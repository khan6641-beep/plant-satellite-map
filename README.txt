식물 위성 지도 사용 안내
========================

1. 프로젝트 개요
----------------
이 폴더는 필요정보.csv의 식물 좌표 12,142개를 위성 지도 위에 표시하는 정적 웹 애플리케이션입니다.
식물 정보, 검색 데이터, CSS, JavaScript, Leaflet, 마커 클러스터링 라이브러리, 아이콘은 모두 폴더 안의 로컬 파일에서 읽습니다.
인터넷 통신은 기본 설정상 위성 지도 타일을 받을 때만 사용합니다. 광고, 분석 도구, 외부 데이터베이스는 포함하지 않았습니다.

주요 파일
- index.html: 지도 애플리케이션
- start.html: 실행 안내 및 시작 페이지
- assets/js/config.js: 위성 타일과 줌·라벨·클러스터 설정
- data/plants-data.js: file:// 직접 실행용 실제 식물 데이터
- data/plants.json: 정적 호스팅 및 데이터 확인용 UTF-8 JSON
- data/data-summary.json: 변환·검증 결과
- source/필요정보.csv: 원본 CP949 CSV
- tools/convert_csv.py: CSV 재변환 스크립트
- TEST-RESULTS.txt: 제작 시 수행한 테스트 결과

2. PC에서 실행하는 방법
-----------------------
가장 간단한 방법
1) ZIP 파일의 압축을 완전히 풉니다.
2) start.html 또는 index.html을 더블 클릭합니다.
3) 인터넷에 연결되어 있으면 위성 지도가 표시됩니다.

직접 파일 실행에서도 식물 데이터는 data/plants-data.js를 script 태그로 불러오므로 fetch()가 필요하지 않습니다.
다만 일부 브라우저는 file:// 환경에서 현재 위치, 서비스 워커, PWA 설치를 제한합니다. 검색·마커·정보 카드는 직접 파일 실행을 기준으로 구성되어 있습니다.

모든 기능을 안정적으로 확인하려면 정적 호스팅을 사용하거나, 선택적으로 이 폴더에서 로컬 HTTP 서버를 실행할 수 있습니다.
Python이 이미 설치된 PC의 선택 사항:
  python -m http.server 8000
그 뒤 브라우저에서 http://localhost:8000 을 엽니다.
이 명령은 필수 실행 조건이 아니며, 최종 사이트 자체에는 서버 프로그램이 필요하지 않습니다.

3. Android에서 실행하는 방법
----------------------------
권장 방법
- GitHub Pages, Cloudflare Pages, Netlify 또는 사내 정적 웹서버에 폴더 내용을 업로드한 뒤 Chrome에서 주소를 엽니다.
- 필요하면 Chrome 메뉴의 "홈 화면에 추가"를 사용합니다. 설치하지 않아도 일반 웹사이트로 사용할 수 있습니다.

로컬 파일 방법
1) ZIP을 파일 앱에서 압축 해제합니다.
2) start.html 또는 index.html을 HTML 열기를 지원하는 브라우저/파일 앱으로 엽니다.
3) Android 제조사와 브라우저 정책에 따라 로컬 HTML 열기, 위치 권한, PWA가 제한될 수 있습니다.
로컬 파일이 열리지 않으면 데이터 문제나 앱 오류가 아니라 모바일 보안 정책일 가능성이 높으므로 정적 호스팅 방식을 사용하세요.

4. iPhone/iPad에서 실행하는 방법
--------------------------------
권장 방법
- 정적 호스팅 주소를 Safari로 엽니다.
- 선택적으로 공유 버튼 > "홈 화면에 추가"를 사용합니다.

로컬 파일 방법
- 파일 앱에서 ZIP을 압축 해제하고 index.html을 열 수 있으나, iOS의 미리보기 화면은 JavaScript, 외부 위성 타일, 현재 위치, 서비스 워커를 제한할 수 있습니다.
- iPhone에서는 정적 호스팅이 가장 안정적인 실행 방식입니다.

5. 정적 호스팅에 업로드하는 방법
--------------------------------
공통 원칙
- plant-satellite-map 폴더 안의 파일과 하위 폴더를 구조 그대로 업로드합니다.
- index.html이 사이트 루트에 있어야 합니다.
- 모든 경로는 상대 경로이며 특정 컴퓨터의 절대 로컬 경로를 사용하지 않습니다.

GitHub Pages 예
1) 새 저장소를 만들고 이 폴더의 내용을 업로드합니다.
2) 저장소 Settings > Pages에서 배포 브랜치를 지정합니다.
3) 생성된 HTTPS 주소를 엽니다.

Cloudflare Pages/Netlify 예
1) 정적 사이트 프로젝트를 만듭니다.
2) 빌드 명령은 비워 둡니다.
3) 출력 폴더는 이 프로젝트 폴더 자체로 지정하거나 폴더 내용을 직접 업로드합니다.

사내 웹서버 예
- 웹서버의 공개 디렉터리에 전체 폴더를 복사합니다.
- 별도 데이터베이스나 서버 측 코드가 필요하지 않습니다.

6. 위성 지도에 인터넷 연결이 필요한 이유
----------------------------------------
위성 영상은 데이터 용량과 공급자 이용 정책 때문에 이 ZIP에 포함하지 않습니다.
브라우저가 화면에 필요한 지도 타일만 assets/js/config.js에 설정된 지도 공급자에게 요청합니다.
서비스 워커는 로컬 앱 파일과 식물 데이터를 캐시하지만 위성 타일을 무제한 사전 다운로드하지 않습니다.
인터넷이 끊겨도 이미 열린 앱의 UI, 식물 마커 데이터, 검색 기능은 사용할 수 있습니다. 캐시되지 않은 지도 영역에는 위성 영상이 나타나지 않을 수 있습니다.

7. 식물 데이터와 개인정보
-------------------------
- 식물 데이터는 data/plants-data.js와 data/plants.json에 로컬로 저장됩니다.
- 검색어는 외부로 전송하지 않습니다.
- 현재 위치는 브라우저 안에서 지도 이동과 정확도 원 표시에만 사용하며 저장하거나 전송하지 않습니다.
- 외부 분석 도구와 광고 스크립트가 없습니다.
- 위성 타일 요청 시에는 지도 공급자가 일반적인 웹 요청 정보(IP 주소 등)를 받을 수 있습니다.

8. 위성 지도 공급자 설정 방법
-----------------------------
assets/js/config.js의 MAP_CONFIG를 수정합니다.

주요 항목
- tileUrl: 타일 URL. {z}, {x}, {y} 자리표시자를 사용합니다.
- attribution: 지도 저작권 문구. 공급자 요구 문구를 정확히 입력합니다.
- minZoom, maxZoom, maxNativeZoom: 줌 범위
- apiKey: API 키가 필요한 타일 서비스의 공개용 키

기본값은 Esri World Imagery URL과 저작권 표시입니다.
지도 공급자 URL이나 정책은 변경될 수 있으므로 실제 배포 전에 기관의 사용 목적과 공급자 약관을 확인하세요.

9. API 키가 필요한 경우
-----------------------
1) assets/js/config.js에서 tileUrl에 {API_KEY}를 넣습니다.
   예: https://example.com/tiles/{z}/{x}/{y}?key={API_KEY}
2) 같은 파일의 apiKey 값에 공급자가 발급한 공개용 브라우저 키를 입력합니다.
3) attribution도 공급자 요구 문구로 변경합니다.

주의
- 브라우저용 정적 사이트의 키는 사용자에게 보일 수 있습니다.
- 비밀 서버 키를 넣어야만 동작하는 서비스는 사용하지 마세요.
- 가능한 경우 도메인 제한, 사용량 제한이 있는 공개용 키를 사용하세요.

10. CSV 데이터를 교체하는 방법
------------------------------
새 CSV는 다음 헤더를 정확히 포함해야 합니다.
  Common_Name,Genus,Species,ItemCoordX,ItemCoordY,origin

좌표 규칙
- ItemCoordX = 위도(latitude)
- ItemCoordY = 경도(longitude)
- Leaflet 좌표 순서 = [ItemCoordX, ItemCoordY]

교체 절차
1) 새 CSV를 source/필요정보.csv로 저장합니다.
2) 프로젝트 폴더에서 아래 변환 명령을 실행합니다.
   python tools/convert_csv.py
3) data/plants.json, data/plants-data.js, data/data-summary.json이 다시 생성됩니다.
4) 브라우저 캐시를 강력 새로고침합니다.
5) 정적 호스팅에 다시 업로드합니다.

다른 파일명을 사용할 경우
  python tools/convert_csv.py "source/새파일.csv"

출력 위치를 바꾸는 예
  python tools/convert_csv.py "source/새파일.csv" --json data/plants.json --js data/plants-data.js --summary data/data-summary.json

11. 변환 스크립트 동작
----------------------
tools/convert_csv.py는 다음 작업을 수행합니다.
- UTF-8 BOM, CP949, EUC-KR 순서로 인코딩 자동 감지
- 앞뒤 공백 제거 및 한글 유니코드 정규화
- 위도 숫자 및 -90~90 범위 확인
- 경도 숫자 및 -180~180 범위 확인
- 완전히 동일한 중복 행 통계
- 동일 좌표 통계(개체는 삭제하지 않고 모두 유지)
- 깨진 대체 문자 여부 확인
- UTF-8 JSON과 file://용 JavaScript 데이터 생성

Python 3이 필요하며 외부 Python 패키지는 필요하지 않습니다.
변환 실패 시 오류 메시지와 종료 코드 1을 반환합니다.

12. 검색과 지도 사용
--------------------
- 검색 대상: 국명, 속명, 종소명, 전체 학명, 표찰번호
- 대소문자를 구분하지 않으며 부분 일치를 지원합니다.
- 검색 결과를 선택하면 해당 위치로 확대하고 마커·국명 라벨을 강조하며 정보 카드를 엽니다.
- 지도 빈 곳이나 선택된 마커를 다시 누르면 카드를 닫습니다.
- 현재 위치 버튼은 브라우저 권한을 요청합니다.
- 전체 범위 버튼은 모든 유효 좌표가 보이는 범위로 돌아갑니다.
- 낮은 줌에서는 라벨을 제한하고, 확대할수록 더 많이 표시하며, 20 이상에서는 화면 안의 개별 마커 라벨을 최대한 모두 표시합니다.

13. 성능 설정 변경
------------------
assets/js/config.js에서 조정할 수 있습니다.
- LABEL_ZOOM_LEVELS: 라벨 표시 줌 단계
- LABEL_LIMITS: 부분 표시 최대 라벨 수
- SEARCH_CONFIG.moveZoom: 검색 결과 이동 줌
- CLUSTER_CONFIG.maxClusterRadius: 클러스터 반경
- CLUSTER_CONFIG.disableClusteringAtZoom: 개별 마커 분리 줌

데이터가 훨씬 많아질 경우 LABEL_LIMITS를 낮추거나 클러스터 반경을 늘리면 모바일 성능에 도움이 됩니다.

14. 오류 해결
-------------
"식물 데이터 파일을 찾을 수 없음"
- data/plants-data.js가 index.html과 함께 같은 폴더 구조에 있는지 확인합니다.

"위성 지도 API 키가 설정되지 않음"
- assets/js/config.js의 tileUrl에 {API_KEY}가 있다면 apiKey를 입력합니다.

위성 영상이 보이지 않음
- 인터넷 연결, 방화벽, 지도 공급자 URL, 공급자 정책을 확인합니다.
- 식물 마커와 검색이 보인다면 로컬 데이터는 정상입니다.

현재 위치가 동작하지 않음
- 브라우저 위치 권한을 허용합니다.
- HTTPS 정적 호스팅을 사용합니다. file:// 또는 HTTP 환경에서는 브라우저가 위치 기능을 제한할 수 있습니다.

모바일에서 로컬 HTML이 열리지 않음
- 모바일 운영체제의 보안 정책일 수 있습니다. 정적 호스팅 방식을 사용합니다.

변경 후 예전 파일이 보임
- 브라우저 캐시를 삭제하거나 강력 새로고침합니다.
- service-worker.js의 CACHE_NAME 버전을 v2처럼 올리면 새 캐시로 교체할 수 있습니다.

15. 이메일 또는 클라우드로 전달
------------------------------
- 최종 전달 파일은 plant-satellite-map.zip 하나입니다.
- 이메일 서비스의 첨부 용량 제한을 넘으면 Google Drive, OneDrive, Dropbox, 사내 파일 공유 등 승인된 클라우드에 ZIP을 올리고 다운로드 링크를 보냅니다.
- 수신자는 ZIP을 완전히 압축 해제한 뒤 사용해야 합니다. ZIP 내부에서 HTML을 바로 열면 브라우저가 하위 파일을 읽지 못할 수 있습니다.
- 조직의 개인정보 및 파일 공유 정책을 따르세요.

16. 포함 라이브러리
-------------------
- Leaflet 1.9.4
- Leaflet.markercluster 1.5.3
두 라이브러리는 assets/vendor 폴더에 포함되어 런타임 CDN에 의존하지 않습니다. 각 폴더에 LICENSE.txt도 포함했습니다.

17. 테스트 결과
---------------
TEST-RESULTS.txt에 데이터 검증, 정적 파일 검사, 데스크톱/모바일 크기 브라우저 자동 테스트, 로컬 파일 실행 및 오프라인 테스트 결과가 정리되어 있습니다.
실제 Android 및 iPhone 기기 정책은 제조사·OS·브라우저 버전에 따라 다르므로 최종 배포 환경의 실기기 점검을 권장합니다.
